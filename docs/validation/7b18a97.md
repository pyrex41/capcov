## Failures and root causes

### F1. `tests.test_claim_contract_review.ContractReviewTests.test_json_ingestion_rejects_unknown_fields_and_bad_version` (base family): failed

The test still asserts that `bundle_from_json` refuses `schema_version: 2`. Commit `960baee` (2026-10-15,
"add Shen specification and v2 authority foundation") added 2 to `SUPPORTED_SCHEMA_VERSIONS` in
`src/capcov/claims/ir.py`. Since then, a v1-shaped document labelled version 2, carrying none of the v2
contract fields, is accepted by the generic `bundle_from_json` (checked directly at this revision).
`{"extra": true}` is still refused. Only the version assertion fails.

One of two things has to be decided, and the decision is not a test-mechanics question:
- the test is stale (it should use `bundle_from_json_v1`, or expect v2 to be accepted), or
- generic ingestion of v2 should require the v2 contract declarations. The docstring of
  `bundle_from_json_v2` says "with explicit evidence-composition declarations", but missing declarations
  are accepted.

Nothing was changed: the code lives in `src/capcov/claims/**`, which another agent is changing.

### F2. Eight Shen tests run in the base family and skip there; the gate fails

`tests.claim_semantics.test_shen_derivation_pins.ShenDerivationPinTest` (4 tests) and
`tests.claim_semantics.test_spec_templates.NativeTemplateTests` (4 tests) need bifrost and shen-go. They are
not listed in `tests/tool-families.json`, so `check-skips.py` puts them in `base`, where they skip. Neither
allowlist names them. Both classes were added recently, in `2acba9e` and the merge `7b18a97`. Run directly in
the shen shell with `CAPCOV_SHEN_REQUIRED=1`, all 8 pass (85.8 s).

**Fix made (separate commit after 7b18a97):** both classes were added to the `shen` family in
`tests/tool-families.json`. This is the documented way to do it (`scripts/check-skips.py` docstring: "A class
that needs a tool and is not listed runs in base, skips or fails there, and fails the run"). See "After the
fix" below for what that commit was run against.

`tests/skips-allowed-plain-python.json` does not name these 8 tests either, so the Earthfile plain-Python
target (`+test`) would also report them as unexpected skips. That target was not executed here: no
Earthly/Docker. The allowlist was left unchanged.

### Known lead: `test_reasoning.py:58` raises `OperationError` instead of skipping without Tree-sitter

`SourceEvidenceTests.test_go_and_php_source_anchors_use_bundled_grammars` calls `extract()` on Go and PHP
files. Without the `treesitter` extra, `src/capcov/operations/evidence.py:121` raises
`OperationError("Go/PHP extraction requires installed Tree-sitter grammars")`, and the test reports an
ERROR.

- **Reproduced in the flake shell:** executed at 7b18a97. In the shen shell with a separate venv that had
  no extras: `Ran 5 tests ... FAILED (errors=1)`, with this traceback.
- **With the CI command** (`--extra treesitter`): executed at 7b18a97. The test passes in base 1/1.
- **Is it a gating bug?** No. An error makes the run fail in both modes of `check-skips.py`:
  `wasSuccessful()` is false, and the shard's `"successful": false` fails the merge. It does not get past
  skip accounting; it is stricter than a skip. Every CI and Earthfile target installs `--extra treesitter`.
  An environment without that extra also makes the other `_HAVE_TS` tests skip with "treesitter extra not
  installed", and no allowlist accepts those skips, so such an environment fails the gate either way. It
  would be more consistent with the rest of the suite if this test also used `skipUnless(_HAVE_TS)`, but
  the gate result would not change, so nothing was changed.
